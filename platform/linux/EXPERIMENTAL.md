# Linux VPN prototype safety limits

This code is experimental and is not ready for distribution. It requires a root-owned service, Linux TUN, iproute2, nftables, systemd-resolved, and `/etc/resolv.conf` configured exclusively to use 127.0.0.53. That DNS check happens at startup; it does not prove that all applications use the system resolver.

While the session firewall is active, local-network access is blocked, except loopback; IPv6 is blocked. Sockets protected by the engine are bound to the original physical device and carry a randomly generated SO_MARK. The nftables OUTPUT hook drops other host-originated traffic sent outside the TUN. Network changes can therefore interrupt connectivity. Packet forwarding for containers, virtual machines, and other transit traffic does not traverse OUTPUT and is not protected by this prototype. A process with sufficient privilege to set a matching mark, alter the firewall, or recreate the TUN interface name can bypass these rules. Existing firewall rules or routing policies may alter behavior and have not been comprehensively tested.

The randomly named firewall table is recorded before creation. After a crash, routes vanish with the nonpersistent TUN but the firewall stays until successful recovery; internet access can remain blocked. Recovery refuses to change an existing interface merely because its name matches the old TUN, preserving the journal for investigation. Concurrent process starts are not yet protected by a cross-process lock. systemd service startup ordering, installation, packaging and end-to-end operation with a real VPN gateway remain untested.
